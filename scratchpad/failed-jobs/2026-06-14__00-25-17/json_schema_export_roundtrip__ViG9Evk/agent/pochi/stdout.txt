The team needs the same User schema to be (a) exportable as a JSON Schema draft-2020-12 document for OpenAPI consumers and (b) re-parsable back into an ArkType `Type` via `@ark/json-schema` so the API gateway can validate against either definition and prove they agree on the same documents. ## Requirements Build a TypeScript module under `/home/user/myproject` that defines a complex User schema and provides three pieces of functionality: 1. An **original ArkType schema** for a User document that includes: * `id`: UUID * `email`: email-formatted string * `username`: an intersected string constraint combining the built-in alphanumeric keyword with a length bound of 3..20 * `score`: a morph that accepts a numeric string and produces a number * `address`: nested object `{ street, city, zip }` where `zip` matches the pattern `^\d{5}(-\d{4})?$` * `posts`: array of `Post`, where each Post has: * `title`: string with length between 1 and 120 (inclusive) * `tags`: array of strings with length between 1 and 10 (inclusive) * `comments`: array of `Comment` * `Comment` is a **recursive** type with: * `id`: UUID * `body`: non-empty string * optional `replies`: array of `Comment` The schema MUST be defined through a cyclic ArkType `scope({ ... }).export()` (not a single inline `type({...})`). 2. A **JSON Schema export** that writes the User definition to `/home/user/myproject/out/user.schema.json`. The exported document MUST include `$schema` set to the JSON Schema draft-2020-12 dialect URL (`https://json-schema.org/draft/2020-12/schema`). 3. A **round-tripped ArkType schema** rebuilt from that JSON Schema using `@ark/json-schema`. The round-tripped schema MUST behave identically to the original on all fixtures the CLI is asked to validate. 4. A **CLI** that reads a single JSON User payload from stdin, runs it through both schemas, and prints exactly two lines to stdout (no other output on stdout, and exit code 0 in all cases): * Line 1: `VALID` if the original ArkType schema accepts the payload, otherwise `INVALID`. * Line 2: a JSON object of the exact shape `{"original":<bool>,"roundtrip":<bool>}` where each boolean reflects whether the respective schema accepts the payload. ## Implementation Hints * The project skeleton already declares `arktype@2.2.0`, `@ark/json-schema@0.0.4`, `tsx`, and `typescript` in `package.json`, and pre-installs `node_modules`. * The CLI is invoked from the project root as `npx --no-install tsx cli.ts`. `cli.ts` should read all of stdin, parse it as JSON, then run both schemas. * `@ark/json-schema@0.0.4` does not implement `$ref`/`$defs`, so re-parsing a cyclic JSON Schema directly will fail.
