```ts
import { type } from "arktype"

export const LooseUser = type({
    name: "string",
    "+": "ignore"   // pass-through (ArkType's default behavior)
})

export const RejectUser = type({
    name: "string",
    "+": "reject"   // undeclared keys → type.errors
})

export const DeleteUser = type({
    name: "string",
    "+": "delete"   // undeclared keys stripped from output
})
```

**How it works:** ArkType 2.2.0 reserves the `"+"` key in object literals as a special directive — its value must be one of the three `UndeclaredKeyBehavior` strings:

| Value | Behavior |
|---|---|
| `"ignore"` | Extra keys pass through untouched (structural, TypeScript-compatible default) |
| `"reject"` | Extra keys cause a `type.errors` validation failure |
| `"delete"` | Extra keys are cloned away; output only contains declared properties |

- `LooseUser({ name: "a", extra: 1 })` → `{ name: "a", extra: 1 }` (`extra === 1` ✓)
- `RejectUser({ name: "a", extra: 1 })` → `ArkErrors` instance (`instanceof type.errors` ✓)
- `DeleteUser({ name: "a", extra: 1 })` → `{ name: "a" }` (`"extra" in result === false` ✓)
- All three accept `{ name: "a" }` without errors ✓
